# suse-lolly

The **SUSE brand pack** for [Lolly](https://github.com/lolly-tools/lolly):
SUSE-specific tool definitions plus the SUSE brand catalog (assets, fonts,
design tokens, generated previews/OG cards). Private - see the NOTICE files.

Consumed by the `lolly` monorepo as a git submodule at `brands/suse/`. The
active profile (see the monorepo's `profiles.json`) resolves tool ids across
`community/` in the main repository and `tools/` here (later roots win on an
id collision) and reads `catalog/` here as the catalog root, through
`packages/node-shell/src/content-roots.ts`. There is no repo-root view any more;
`pnpm run profile` prints what is resolved.

```
tools/     # 15 SUSE tool definitions (brand-lockup, pose-geeko, digi-ad, …)
catalog/   # assets/suse/** (incl. tokens/brand.json), fonts/, previews/, og/, tools/index.json
```

- `catalog/tools/index.json` is **generated** by the monorepo's
  `pnpm run build:catalog` (run against the `suse` profile) - do not hand-edit.
- `catalog/assets/suse/tokens/brand.json` is the DTCG design-token document
  generated by `scripts/build-brand-tokens.ts`.
- Logos and dynamic icons remain bundled with the fonts, palettes and tokens.
  Photos, campaign images, executive portraits, backgrounds and illustrations
  come from the organisation's configured Brandfolder connector.
- `catalog/assets/suse/music/` (the PremiumBeat stock-music tracks) was removed
  on 2026-08-29 - no PremiumBeat-licensed audio ships anywhere (see `catalog/NOTICE.md`).
- The pack carries no audio. The public-domain focus music (`lolly/loops`,
  `lolly/modules`, `lolly/songs`) was removed on 2026-11-04; Lolly's own catalogs
  keep it, and lolly.ing gets music beds from Brandfolder or uploads.
- Each file is kept once. The `3d` tool reads its Geeko samples from the catalog
  (`suse/model/*`, the same files 3D Studio uses) instead of its own copies, and
  the fonts ship as `ttf/`, `variable/` and `webfonts/` (no duplicate `otf/`).

The asset index supplies no brand-specific trusted-site defaults. Configure
reviewed hosts through the organisation's site policy, or let each person approve
a site when asked. These entries control consent prompts; they do not expand the
application's Content-Security-Policy or authorise connector network requests.

Older profiles may already contain the former brand defaults as personal entries.
The stored list has no provenance that distinguishes those entries from deliberate
personal choices. Review and remove unwanted entries in the profile, or configure
an organisation `allowlist-only` policy to ignore personal entries. For a governed
deployment, use individually approved hosts and disable inherited brand defaults;
configure connector origins separately in the application build and web headers.

Split out of the public
[`lolly-suse-tools`](https://github.com/lolly-tools/lolly-suse-tools) +
[`lolly-suse-catalog`](https://github.com/lolly-tools/lolly-suse-catalog)
repos (2026-07-08); community-safe tools moved to the public `lolly-tools`
repo.

Licensing is mixed and mostly proprietary - see `tools/NOTICE.md` and
`catalog/NOTICE.md`.

## lolly.ing preview image

`.github/workflows/lolly-ing-preview.yml` builds the private lolly.ing instance image (Work server, SUSE shell and
pack) from three exact commits, signed with lolly.ing's own catalog key in the `lolly-ing-signing` environment. The
image stays an artifact of the private run and is never pushed to a registry. See
[docs/lolly-ing-preview.md](docs/lolly-ing-preview.md) for the jobs, the artifacts and the environment, secret and
variables it needs.
